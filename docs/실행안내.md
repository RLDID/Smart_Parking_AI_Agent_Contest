# 로컬 실행과 시연

## 설치·기동

[README](../README.md)의 두 터미널 방식으로 실행합니다. 기존 `.venv`가 있다면 재생성하지 않습니다. 백엔드 DB는 `data/local/contest.sqlite3`에 생성되며 Git에서 제외됩니다. 의존성 설치에는 인터넷이 필요합니다.

프론트8000은 API·상태·개발 콘솔 요청을 백엔드8010으로 전달합니다. 이 실행은 loopback 로컬 시연용이며 인터넷 공개 서비스 배포가 아닙니다. 두 포트가 사용 중이면 기존 개발 서버를 정상 종료한 뒤 실행합니다.

## 시나리오 제어

1. `http://127.0.0.1:8000/?mode=live`에서 `demo-operator`로 로그인합니다. `로컬 시험 제어`에서 상황과 새 시험 회차를 선택하고 관측 시간을 진행합니다. 새 DB에는 기존 회차가 없습니다.
2. `http://127.0.0.1:8000/devtools/operations`를 같은 운영자 프로필에서 열어 업무 Agent를 명시적으로 시작/처리합니다. 기본 판단 모드는 모의입니다. 로그인·회차 생성만으로 Agent가 시작되지 않습니다. 관측 준비·시간 제어는 `/devtools`를 함께 사용합니다.
3. S1-a/b/c는 연락과 응답 이후 합성 이동·재주차를 입력하고 지속 공간 회복을 확인합니다. 차주 프로필에서 알림·응답을 보여주며 `응답`과 `사건 해결`을 구분합니다.
4. S2는 합성 경보 상태와 Agent의 소유자 보고를 각각 확인합니다. 화면의 장치 상태를 실제 스피커 출력으로 해석하지 않습니다.
5. S3는 명령을 생성·구체화하고 계획을 확인합니다. 정식 화면의 `모의 계획 준비`와 `모의 업무 한 단계 처리`는 일시정지 회차에서 사용합니다. 합성 방송 결과·신규 입차 제한·출차 유지·후속 완료를 확인합니다.

시나리오는 통로차단 `s1a-foundation-v1`, 출차방해 `s1b-blocked-v1`, 주차면침범 `s1c-overlap-v1`, 접근위험 `s2-crossing-v1`, 운영명령 `s3-closing-v1`입니다. S1-a는 `foundation-v1`, 나머지는 `sim0-v1` 구성을 사용합니다.

## 실제 모델 선택

실제 제공자 키와 결제·모델 접근권한을 준비한 경우에만 실행합니다. 키는 백엔드 환경변수 `OPENAI_API_KEY`, `GEMINI_API_KEY`로 공급하고 `VITE_*`·프론트·소스에 넣지 않습니다. `.env.example`은 설명용이며 자동 로딩하지 않습니다.

```powershell
.venv\Scripts\python.exe code/frontend/scripts/run-integration-backend.py --live-config data/samples/live-read-defaults.json
```

정식 화면의 AI 조회에서 제공자를 선택해 보낸 요청은 비용이 발생합니다. 자동 업무는 개발 콘솔에서 live 시작을 별도로 선택하며 위 명령만으로 켜지지 않습니다. 기본 업무 모델은 GPT-6 Luna, 보조는 Gemini 3.8 Flash이고 모의 경로는 별도로 유지합니다. 사용 가능 여부는 제공자 계정에 따릅니다. 전송 결과가 불명인 요청을 무조건 다시 보내지 않습니다.

## 종료·복구

각 서버 터미널에서 `Ctrl+C`로 종료합니다. 같은 명령으로 다시 실행하며 DB를 삭제하지 않습니다. 복구 회차는 정지/복구 확인 상태에서 운영자가 다시 진행합니다. 프론트와 백엔드는 단일 로컬 인스턴스로 운용합니다.

## 선택적 재현 도구

```powershell
.venv\Scripts\python.exe -m pytest -q
```

프론트 폴더의 `npm test`, `npm run build`는 각각 프론트 단위 검사와 타입 검사/빌드입니다. 이 명령들을 소스 배포 준비 때 모두 새로 실행했다는 뜻은 아닙니다. 각 도구의 `--help`와 모드·출력 경로를 확인한 뒤 별도 평가를 선택합니다. 평가 정답은 제품 Agent의 관측이나 검색 자료로 사용하지 않습니다.
